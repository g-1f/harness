Callable Skill Graph Patterns

A node is one task: an atomic reasoning trace that runs a skill from the graph, or none. Nodes split the what into child nodes, stay aware of each other through one stream of lines each, and talk by publishing addressed artifacts. Everything on this page is written against six host calls.

This page describes v3, which is designed and not yet built. Every animation is hand-authored from the design and compiled by a script that checks it against the rules below, so the calls, lines, holds and versions follow v3's semantics; the timing is illustrative. Select any node to see exactly what it sees.

Six host calls

These are the only operations the host implements for node code. Each exists because code alone cannot enforce its identity, lifetime or delivery. Nothing else is hard-coded: no summaries, no declared provenance, no reuse flags.

Read

readNode({node})

Load a skill's procedure, links and resources from the pinned registry. The read is recorded as consulted; nothing runs.

readArtifact({ref, offset, limit})

Read a bounded slice of any ref in the run: a checkpoint n7.c3, a result n7.r2, a node record n7 with its exact request, a trail n7.trail, a message you.m1, or the index run.

Run

openNode({request})

Start a node, join identical work that is running, or reuse its latest result if it finished. Returns at once. Failed work is never joined; from forks a trail.

nextNodeEvent({after})

The node's one stream: everything pending since the cursor, or wait if nothing is. The same lines are pushed at each turn boundary while the node is busy.

closeNode({handle})

Release this hold. Unfinished work is cancelled only when its last holder leaves.

Write

publishCheckpoint({content, to})

Publish free-form content as the next checkpoint. Its first line becomes its line; refs written in it are its links. With to it is addressed to a node or to you, and a finished node is reopened by it.

the final message

Not a call. When a node ends, its final message is stored as its next result: n7.r1, then n7.r2 after a reopen. A node cannot end while it holds unfinished work.

What a node sees

Every start, join, checkpoint, result, close and reopen in the run becomes one line in every node's stream: who, the first line of the content, and its ref into the run's database. Lines addressed to the node or about work it holds are marked. Nothing else enters its context: it reads an artifact, a record or a trail only when it chooses to. A node that opens late starts from the index, one line per node, and every batch ends with the budget left.

Helpers used by the patterns below
The harness guarantees
  • Exact-match sharing by identity; failed work is never joined.
  • A start line is in every stream before openNode returns.
  • One ordered stream per node, delivered at turn boundaries, never dropped.
  • Work lives while anyone holds it; the last release cancels it.
  • A node cannot end while it holds unfinished work.
  • An addressed artifact reopens a finished node; its next result is a new version, and old versions never change.
  • Inline refs are checked against the run; reads and trails are recorded.
  • Caps on nodes, calls, depth and time, with the budget left in every batch.
  • Any node can read any ref in its run; runs are walled off from each other.
The model decides
  • How to split a task into orthogonal tasks, and how deep to go.
  • Whether to join, fork, cite, or run something separately.
  • What to read, and when.
  • Whom to address, and what to say.
  • When to steer a child, and when to close it.
  • How to settle a disagreement.
  • Which results news touches, and what to reopen.

Traversal

How work spreads over the skill graph. Links in prose are hints; a node opens what it judges it needs, and refs written into tasks and results carry everything between nodes. Hover a primitive to find it in the code; select a node to see its stream.

Coordination

How nodes that can see each other cooperate: join what is already running, fork a trail for a different aspect, settle a disagreement by talking, steer a child, ask you, and reopen on news. Each is a few lines of code over the six calls, not a protocol.

Validation and recovery

Checks are nodes over exact versions, and recovery is ordinary control flow. A failing verdict is a published artifact; what it means is the caller's decision.

How this page was made

v3 is designed, not built. Every animation on this page is hand-authored from the design and compiled by a script that numbers refs, derives every line, hold and edge, and checks the timeline against v3's rules: ids follow opening order, refs are cited only after they exist, no node ends while it holds unfinished work, joins land only on running work and reuse only on finished work, and an addressed artifact reopens a finished node. Timing is illustrative: one step is one beat of the run, not a measured duration.

The node code is what a model would write in its PTC cells. A gap between cells is where the model reads what came back and decides; no regex or rule stands in for that judgment. Data pulls and arithmetic happen inside nodes as ordinary tool calls and are not drawn.
