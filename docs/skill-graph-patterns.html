Callable Skill Graph Patterns

A skill is a prose procedure. The harness runs it as a node: a function from an explicit request to one immutable artifact. Nodes compose by writing ordinary JavaScript against eight host primitives, and every graph shape on this page comes from that code.

Each code block ran through the harness in QuickJS, and each graph replays the event log from that run: which node started, which caller joined or reused shared work, what was published and what was passed on as evidence. Leaves are scripted stand-ins for model work, so the timing is illustrative; the calls, sharing and lifetimes are the runtime's own.

Eight host primitives

These are the only operations the host implements for node code. Each one exists because JavaScript alone cannot enforce its lifetime, authority or publication effect. They are defined once in harness/api.py and exposed identically to the agent adapter and the code runner.

Read

readNode({node})

Load a pinned procedure: prose, links and resources. The read is recorded as consulted; nothing runs.

readArtifact({ref, offset, limit})

Read a bounded slice of immutable evidence after checking the grant and integrity. Knowing a hash is not a grant.

Call

runNode({request})

Start, join or reuse work and wait for the final receipt. Grants only the final artifact.

openNode({request})

Admit a request and take a caller-owned lease without waiting.

nextNodeEvent({handle, after})

Deliver the next checkpoint or the terminal result, in order. Grants what it delivers.

closeNode({handle})

Release this caller's lease. Unfinished work is cancelled only when its last caller leaves.

Write

publishCheckpoint({summary, content, based_on})

Freeze intermediate output and announce it to current and late subscribers. It survives a later failure.

submitCandidate({summary, content, based_on})

Stage the node's return value. It is published only after every child call is joined or closed.

Traversal patterns

How a run moves through the skill graph. Links in prose are hints; calls in code become executions; refs carry artifacts between them. Hover a primitive to find it in the code; select a node to see its task, callers and artifact.

Validation and recovery

Checks are nodes over exact artifacts, and recovery is ordinary control flow. The runtime never reads a verdict; the calling code decides what a failing one means.

Compositions

The same primitives, combined. Each larger graph is the atomic patterns above running together. Select a pattern under "Built from" to highlight where it appears in the graph.

How this page was made

Every pattern was executed against g-1f/harness at bde4d66. Orchestrating nodes ran the JavaScript shown, with the two helpers prepended, through the harness code runner in QuickJS. In production these would be agent nodes writing equivalent code from their prose. Leaves are Python stand-ins with fixed delays and canned content.

The runtime's event log was timestamped during the run. Each graph is rebuilt from that log: executions from admissions, edges from lease acquisitions and their dispositions, evidence from request refs, and read-only procedures from consultation events. Playback is slowed to between 3.5 and 9 seconds per run.

Every run was checked before export: the behavior each pattern claims (a join, a reuse, a cancelled loser, a failing joint audit, an approval bound to the reviewed draft) was asserted, and no run left a lease, handle or dependency edge behind.
